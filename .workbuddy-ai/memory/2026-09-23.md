# EK 2: GitHub bölümü tamamen bozuktu (07:30–07:40)

Çöken dev sunucusunun logunda tekrarlayan bir hata vardı:
`GET /api/github/?username=TARIKELER-TARNAK 500` + `GitHub hatası: 404`.
Yani sitenin GitHub bölümü **her yüklemede** hata veriyordu. Kök neden iki katmanlı:

## 1) VERİ hatası — yanlış kullanıcı adı
- `src/lib/content.ts` içindeki **paketlenmiş varsayılan**: `tarikelertarnak` ✓
- `data/content.json` içindeki **kayıtlı canlı içerik**: `TARIKELER-TARNAK` ✗
- GitHub API: `TARIKELER-TARNAK` → **404**, `tarikelertarnak` → **200**
- `data/content.json` **git'te takipli** → yani production'a giden değer bu.
  Düzeltildi: `tarikelertarnak`.

## 2) KOD hatası — 404 ile kesinti AYIRT EDİLMİYORDU (asıl önemli olan)
`fetchUserProfile`/`fetchUserRepos` düz `Error` fırlatıyordu, bu yüzden route
"kullanıcı YOK (404)" ile "GitHub'a ulaşılamadı (ağ/5xx)" durumunu ayırt
edemiyordu. **İkisi de** kullanıcıya şunu gösteriyordu:
> "GitHub'a bağlanılamadı. Lütfen daha sonra tekrar deneyin."

Bu **yanıltıcı**: GitHub erişilebilirdi, sorun yazım hatasıydı. Kullanıcı
sonsuza kadar "tekrar dener" ve hiçbir zaman düzelmez.

**Çözüm**: `GitHubApiError` (HTTP durum kodunu taşır) + `isGitHubNotFound()`.
Route artık 404'te `{ notFound: true }` ve **ne yapılacağını söyleyen** bir
mesaj döner: *"…adlı GitHub kullanıcısı bulunamadı. Yönetim panelinden GitHub
kullanıcı adını kontrol et."* 5 adet `throw new Error(...)` sitesi tipli hataya
çevrildi.

**Genel ders**: Bir hata mesajı "sonra tekrar dene" diyorsa ama sorun kalıcıysa
(yanlış veri, yanlış yapılandırma), mesaj kullanıcıyı **yanlış yönlendirir**.
404 ile 5xx'i ayırt etmek sadece nezaket değil — hatanın çözülebilmesi için şart.
